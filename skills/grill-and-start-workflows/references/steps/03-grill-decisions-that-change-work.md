# Step 3: Grill Decisions That Change Work

Interview the user until every decision that changes the work map is settled. Keep the depth of a grilling session and drop questions that lead nowhere.

## Skip conditions

Skip to step 4 when the work map has no open decision.

## Instructions

1. **Test each question.** Keep it only if the answer changes at least one of these. Otherwise take the sensible default if it is reversible and inside your approval rules, and report it in step 4. If it is not, ask it. A default can settle a detail, but never whether to start an item or which skill runs.
   - Which skill or owner runs next.
   - What is in or out of scope, or what acceptance means.
   - The order of work between projects.
   - Money, risk, or who has authority.

2. **Map a design tree.** Every decision branches into the decisions that depend on it. The **frontier** is every decision whose prerequisites are settled. A question that depends on an answer still open belongs to a later round.

3. **Ask in rounds.** Follow the user's stated preference for one topic or a batch. Otherwise ask the most consequential frontier decisions together. Use a question tool when the host allows it and plain text when it does not, and always leave room for an answer in the user's own words.

4. **Use this card for each question.**

```
Question: <the decision, with the fact it rests on>
Recommendation: <choice and the reason>
If <choice A>: <the skill or workflow that runs, and what it costs or risks>
If <choice B>: <the skill or workflow that runs, and what it costs or risks>
```

A card that would start `/composure:pursue` names the goal and the acceptance check, because the campaign keeps running by itself once started.

In plain text, word the question so "yes" accepts the recommendation.

5. **Recompute after each answer.** Update the work map, remove questions the answer settled, and look up new facts yourself. Keep independent fact finding running while you wait. Silence and elapsed time are not answers.

6. **Stop when the frontier is empty for the agreed scope.** The user can also stop early and accept the current state. Unrelated future questions get parked with a reason.

## Deliverable

The settled decisions with the user's own words, the defaults taken, and the updated work map.
